# 脱敏与发布说明

本仓库提供 MaiBot + NapCat 聊天桥接程序的独立源码副本，包含可选的 Windows 普通 ChatGPT 窗口任务服务。发布副本与私人运行目录分别维护。

## 分支

- `main`：只有一次空根提交，文件树为空。
- `develop_with_window_needed`：从空的 main 派生，包含完整实现和通用配置示例。可选窗口后端需要交互式 Windows 桌面；默认关闭。普通聊天使用 Docker 内的 MaiBot 与 API。

## 不包含的内容

- API Key、OneBot/NapCat/桌面任务服务令牌和登录凭据。
- QQ 账号和真实群号、聊天记录、消息回执、数据库、运行日志及历史任务。
- 私人人设提示词、角色参考图和其他用户附件。
- 本机生成的配置、模型目录、备份、缓存、下载文件和 QQ 登录态。
- 私人 Git 历史、个人提交身份、SSH 私钥及本机绝对路径。
- 便携 Node、编译后的程序和下载的第三方源码；保留构建源码、依赖声明、镜像摘要及上游来源锁定信息。

只有 `config/examples/` 中的通用示例进入版本管理，所有示例密钥为空。部署时使用 `run.cmd init` 或 `sh run.sh init` 初始化自己的 `config/local/`，然后配置 QQ、群号、模型与凭据。锁定的 QQ 连接器由初始化脚本下载。

## 可选窗口后端

完整源码位于 `services/desktop-worker/`，统一通过 `run.cmd worker-*` 管理。Node.js 22.13+ x64 和 .NET Framework 4.x 为该可选组件的宿主要求；只运行 API 核心时不需要它们。编译方式与任务恢复说明见 [混合任务服务](hybrid-worker.md)。

Codex ACP 接入尚未实现，不能把本分支当作已经完成 Codex 后端的版本。

## 发布检查

发布前扫描全部待提交文件：检查私人凭据的实际值、QQ 标识、个人路径、常见密钥格式和排除目录；使用全新 Git 历史避免带入旧版本敏感信息。独立副本还会执行离线回归测试、任务服务测试与 Windows 原生编译，不在发布检查中向 QQ 或真实模型发消息。

本次独立副本验证：28 项 Python 离线回归与 9 项 Node 任务服务测试全部通过，Windows 原生组件编译通过。Python 测试在禁用网络的容器中执行；这不代替真实窗口操作及 QQ 收发验收。

这份检查针对本次源码快照。后续提交仍需自行检查，不能仅依赖 `.gitignore`：Git 已跟踪的文件不会因后来加入忽略规则而自动移除。
